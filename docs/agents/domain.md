# 领域文档

本文件规定工程 skills 在探索代码库时如何读取领域文档。

## 当前布局

本仓库采用 single-context：

- 根目录 `CONTEXT.md`：领域术语和上下文
- `docs/adr/`：架构决策记录

这些文件按需创建，本次初始化不会创建空的 `CONTEXT.md` 或 ADR。

## 探索前读取

开始代码探索前：

- 若根目录存在 `CONTEXT.md`，先读取它。
- 若存在 `CONTEXT-MAP.md`，按其中映射读取与任务相关的 `CONTEXT.md`。
- 读取 `docs/adr/` 中与当前工作区域相关的 ADR。

若文件不存在，静默继续，不要仅因缺失而建议提前创建。`/domain-modeling` 会在领域术语或决策真正明确时按需创建它们。

## 使用统一术语

Issue 标题、重构建议、假设和测试名称应使用 `CONTEXT.md` 定义的领域术语，避免改用词汇表明确排除的同义词。

若所需概念尚未记录，应先判断它是代码库未采用的表述，还是需要通过 `/domain-modeling` 补充的真实领域缺口。

## 标记 ADR 冲突

若输出与已有 ADR 冲突，必须明确指出，不得静默覆盖：

> 与 ADR-0007 冲突，但值得重新讨论，因为……
